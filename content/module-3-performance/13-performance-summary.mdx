## Domain 3 at a Glance

Domain 3 (Performance) is worth **24% of the SAA-C03 exam**. Questions test your ability to select the right AWS service and configuration to meet performance requirements.

## Storage Performance Decision Tree

```
Need storage for EC2?
├── Single instance → EBS
│   ├── General workloads → gp3 (default)
│   ├── High IOPS (DBs, trading) → io2
│   ├── Big sequential reads → st1
│   └── Temporary/fastest I/O → Instance Store (ephemeral!)
├── Multiple Linux instances → EFS (NFS, auto-scales)
├── Multiple Windows instances → FSx for Windows
├── HPC / ML training from S3 → FSx for Lustre
└── Object storage (any service) → S3
```

## Database Performance Selection

| Need | Service | Key feature |
|---|---|---|
| Relational, high reads | Aurora + Read Replicas | 15 replicas, auto-scaling |
| Global relational, <1s replication | Aurora Global Database | Cross-region active-passive |
| Key-value, millisecond latency | DynamoDB on-demand | Serverless, auto-scale |
| Key-value, microsecond latency | DynamoDB + DAX | In-memory cache layer |
| Multi-region active-active NoSQL | DynamoDB Global Tables | Multi-master, sub-second replication |
| Sub-millisecond cache | ElastiCache Redis | Sessions, leaderboards, rate limiting |
| Analytics / Data warehouse | Redshift | Columnar, MPP, petabyte scale |
| Ad-hoc SQL on S3 | Athena | Serverless, $5/TB scanned |
| Full-text search | OpenSearch | Inverted index, dashboards |

## Compute Performance Selection

| Need | Instance Family |
|---|---|
| Variable CPU load | T-family (burstable) |
| High CPU ratio | C-family |
| High memory ratio | R-family |
| HPC / GPU training | P-family |
| GPU inference | G-family |
| NVMe local storage | I-family |
| Tightly coupled HPC | Cluster PG + EFA |

## Content Delivery

| Need | Service |
|---|---|
| Cache web content globally | CloudFront |
| Protect web app at edge | CloudFront + WAF |
| Accelerate uploads from global users | S3 Transfer Acceleration |
| Static IP for global app | Global Accelerator |
| TCP/UDP global routing | Global Accelerator |
| Private file access (authenticated users) | CloudFront Signed URLs |

## Analytics Pipeline

```
Raw data (logs, events, clickstream)
    ↓
Kinesis Data Streams (real-time ingestion)
    ↓
Kinesis Firehose (deliver to S3, buffered)
    ↓
S3 (data lake in Parquet format)
    ↓
Glue (ETL: clean, transform)
    ↓
Athena (ad-hoc SQL) or Redshift (BI queries)
    ↓
QuickSight (dashboards)
```

## Common Exam Traps

1. **S3 is object storage** — cannot be mounted as a file system on EC2 without additional software
2. **EFS is Linux only** — for Windows shared file access, use FSx for Windows
3. **Instance Store is ephemeral** — data lost on stop/terminate. Never for durable data.
4. **DAX is DynamoDB-specific** — cannot be used to cache RDS queries
5. **Athena cost** — charges per data scanned. Use Parquet + partitions to reduce costs significantly
6. **Kinesis Firehose has 60-second minimum delay** — not real-time
7. **CloudFront caches at edge** — reduces origin load. Global Accelerator does NOT cache.
8. **Read replicas don't auto-promote** — must be promoted manually on primary failure (unlike Multi-AZ which auto-fails over)
