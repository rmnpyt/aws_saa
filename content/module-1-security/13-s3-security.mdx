## S3 Security Layers

Amazon S3 has multiple security layers you need to understand for the exam:

1. **Block Public Access** — account-level or bucket-level safeguard
2. **Bucket Policies** — resource-based JSON policies
3. **IAM Policies** — identity-based access control
4. **ACLs** — legacy per-object access control (largely deprecated)
5. **Pre-signed URLs** — time-limited access delegation
6. **Access Points** — named network endpoints with custom policies
7. **Object Lock** — WORM (Write Once, Read Many) protection

## Block Public Access

**S3 Block Public Access** is a set of settings that override any bucket policy or ACL that would make objects publicly accessible:

| Setting | What it blocks |
|---|---|
| Block all public access | Enables all four settings below |
| BlockPublicAcls | Rejects PUT requests with public-granting ACLs |
| IgnorePublicAcls | Ignores all ACLs (even existing ones) |
| BlockPublicPolicy | Rejects bucket policies granting public access |
| RestrictPublicBuckets | Restricts public access even if a policy exists |

**Account-level Block Public Access**: Can be set to block all public access for every bucket in the account — the safest setting. Even if someone creates a new bucket with a public policy, it won't work.

<ExamTip>
Block Public Access settings can exist at the **account level** AND the **bucket level**. The account-level setting takes precedence. If both are set, the more restrictive applies. This is the primary mechanism to prevent S3 data leaks.
</ExamTip>

## Bucket Policies

A **bucket policy** is a resource-based IAM policy attached to an S3 bucket. It controls access to the bucket and its objects.

**Common patterns:**

**Force HTTPS:**
```json
{
  "Effect": "Deny",
  "Principal": "*",
  "Action": "s3:*",
  "Resource": ["arn:aws:s3:::my-bucket", "arn:aws:s3:::my-bucket/*"],
  "Condition": {"Bool": {"aws:SecureTransport": "false"}}
}
```

**Allow cross-account access:**
```json
{
  "Effect": "Allow",
  "Principal": {"AWS": "arn:aws:iam::ACCOUNT_B:root"},
  "Action": ["s3:GetObject"],
  "Resource": "arn:aws:s3:::my-bucket/*"
}
```

**Allow only from a specific VPC endpoint:**
```json
{
  "Effect": "Deny",
  "Principal": "*",
  "Action": "s3:*",
  "Resource": ["arn:aws:s3:::my-bucket", "arn:aws:s3:::my-bucket/*"],
  "Condition": {"StringNotEquals": {"aws:SourceVpce": "vpce-xxxxxxxx"}}
}
```

## Pre-signed URLs

A **pre-signed URL** is a time-limited URL that grants temporary access to a specific S3 object — for either GET (download) or PUT (upload). The URL encodes credentials and an expiration time.

**Use cases:**
- Share a private video with a user for 1 hour
- Allow a user to upload a file directly to S3 without exposing AWS credentials
- Provide temporary download links in a web application

**Important facts:**
- Generated by an AWS SDK using the credentials of the signing identity
- If the signing identity loses permissions before the URL expires, the URL still works until it expires
- Expiration can be set from seconds to 7 days (for IAM roles) or longer (for IAM users, up to legacy limits)

## S3 Access Points

**S3 Access Points** simplify access control for large shared datasets:

- Each access point has a unique hostname and its own access policy
- Restrict access by: VPC (only from a specific VPC), IP address, user/role
- Useful when different applications need different levels of access to the same bucket

```
Bucket: data-lake-bucket
├── Access Point: analytics-ap  (full read, no write, only from analytics VPC)
├── Access Point: etl-ap        (read/write, only from etl-service role)
└── Access Point: reporting-ap  (read-only, only from specific IP range)
```

## Object Lock (WORM)

**S3 Object Lock** prevents objects from being deleted or overwritten for a defined retention period. Implements a WORM model.

**Modes:**
- **Governance mode**: Objects cannot be deleted/modified by most users; can be overridden by users with special permissions
- **Compliance mode**: No one can delete the object or shorten the retention period, including the account root — immutable. Used for regulatory compliance (SEC Rule 17a-4, FINRA).

**Use cases:** Regulatory compliance, ransomware protection, audit logs.

## S3 MFA Delete

**MFA Delete** requires MFA to:
- Permanently delete an object version
- Suspend versioning on a bucket

Can only be enabled by the root user via the CLI. Adds strong protection for versioned buckets.

## Summary

- **Block Public Access**: First line of defense. Enable at account level by default.
- **Bucket Policy**: Resource-based policy for cross-account access, VPC-only access, HTTPS enforcement.
- **IAM Policy**: Identity-based access for IAM users and roles in same account.
- **Pre-signed URLs**: Temporary, time-limited access to specific objects (get or put).
- **Access Points**: Named endpoints with their own policies for multi-application access to shared buckets.
- **Object Lock / Compliance mode**: True WORM — immutable for regulatory requirements.
