## RDS Cost Optimization

**RDS pricing components:**
- DB instance hours (on-demand or reserved)
- Multi-AZ deployment (doubles instance cost)
- Storage (gp2 or gp3 per GB-month)
- I/O requests (for io1 storage)
- Data transfer out
- Backup storage beyond retention

### Strategies

**1. Reserved Instances for production databases**
Production databases running 24/7 should use Reserved Instances:
- 1-year no-upfront: ~30% savings
- 3-year all-upfront: ~69% savings

**2. Don't use Multi-AZ for dev/test**
Multi-AZ doubles the instance cost. Dev/test environments rarely need HA — use single-AZ instances.

**3. Use Aurora over RDS for MySQL/PostgreSQL at scale**
Aurora is often MORE cost-efficient despite higher per-unit prices:
- Aurora storage grows/shrinks automatically (no over-provisioning)
- Aurora Replicas share storage (adding a replica doesn't double storage)
- Aurora is ~3x faster = smaller instance can handle same load = lower cost

**4. Use Aurora Serverless v2 for dev/test and variable workloads**
- Scales down to minimum (0.5 ACU) during off-hours
- Eliminating the idle cost of a t3.medium DB during nights/weekends

**5. Automate snapshot management**
- RDS automated backups: Free within backup retention window
- Manual snapshots: Charged. Delete old ones you no longer need.

**6. Storage type selection**
- **gp3** (for most RDS): Predictable pricing, can tune IOPS separately
- **gp2**: IOPS tied to size (growing volume for IOPS may cost more than gp3)
- **io1**: Only when you need >16,000 IOPS (expensive — avoid unless necessary)

## Aurora Cost Specifics

**Aurora storage billing**: Charged per GB-month for what you actually use (not provisioned):
- No need to pre-provision storage — pays for actual data
- Storage freed when you delete data

**Aurora I/O billing (standard Aurora)**:
- Charged per million I/O requests ($0.20/million for standard)
- High I/O workloads may prefer **Aurora I/O-Optimized** (higher base rate but unlimited I/O included)

**Aurora I/O-Optimized**: Higher storage cost but no I/O charges. Better when I/O costs exceed the premium:
- Rule of thumb: Use I/O-Optimized when I/O charges > 25% of total Aurora cost

## DynamoDB Cost Optimization (Summary)

**Key principle**: Choose provisioned (with auto-scaling) for predictable workloads, on-demand for unpredictable.

| | Provisioned + Auto-Scaling | On-Demand |
|---|---|---|
| Cost when steady | ~6x cheaper per WRU/RRU | More expensive per unit |
| Cost when idle | Pay for minimum capacity | Nothing |
| Cost during spikes | May throttle if auto-scaling too slow | Handles instantly, pay per use |
| Reserved | Available (1 or 3 year, up to 77% off) | Not available |

**When to use On-Demand over Provisioned:**
- Truly unpredictable traffic (early-stage apps)
- Bursting well beyond provisioned capacity regularly
- Apps that see massive spikes (Black Friday, viral content)

## Reducing ElastiCache Costs

**ElastiCache pricing**: Per node-hour based on node type.

**Strategies:**
- **Reserved Nodes**: Commit to 1 or 3 years — up to 55% off
- **Right-size nodes**: Monitor actual memory utilization. Most clusters are over-provisioned.
- **Valkey (open-source Redis fork)**: ElastiCache for Valkey may offer different pricing (newer option)
- **TTL on all keys**: Prevent unbounded memory growth; evict unused keys

## Choosing the Right Database for Cost

| Use case | Most cost-efficient choice |
|---|---|
| Simple key-value, variable traffic | DynamoDB On-Demand |
| Relational, steady workload | RDS or Aurora + Reserved |
| Relational, variable workload | Aurora Serverless v2 |
| Session storage / caching | ElastiCache (vs. paying for DB queries) |
| Analytics queries on S3 data | Athena (no DB needed) |
| Time-series data | Amazon Timestream |
| Search | OpenSearch (vs. SQL LIKE queries) |

## Summary

- **RDS Reserved**: 30-69% off for production databases with predictable usage.
- **No Multi-AZ in dev/test**: Halves the instance cost.
- **Aurora vs. RDS**: Aurora often cheaper at scale due to storage efficiency and speed.
- **Aurora Serverless v2**: Cost-efficient for variable workloads and dev/test.
- **DynamoDB provisioned**: ~6x cheaper per request when load is predictable.
- **DynamoDB Reserved Capacity**: 77% off for steady-state workloads.
- Always use the purpose-built database — using the wrong one wastes money.
