## EC2 Pricing Models Overview

The right pricing model can reduce EC2 costs by 50-90%:

| Model | Discount vs. On-Demand | Commitment | Interruption |
|---|---|---|---|
| **On-Demand** | 0% | None | Never |
| **Reserved Instances** | Up to 72% | 1 or 3 years | Never |
| **Savings Plans** | Up to 66% | 1 or 3 years | Never |
| **Spot Instances** | Up to 90% | None | Yes (2-min warning) |
| **Dedicated Hosts** | Up to 70% (with RI) | Optional | Never |
| **Dedicated Instances** | Higher cost | None | Never |

## On-Demand Instances

Pay per second (or per hour for older types) with no upfront cost or commitment.

**When to use On-Demand:**
- Unpredictable workloads that can't be interrupted
- Short-term spikes
- Development, testing, experimentation
- Applications running less than 1 year

## Reserved Instances (RIs)

Commit to a specific instance type in a specific region for 1 or 3 years:

| Payment option | Discount |
|---|---|
| No upfront | Smallest discount |
| Partial upfront | Medium discount |
| All upfront | Largest discount (~72%) |

### RI Types

**Standard RIs**: Fixed instance family, size, OS, tenancy, and region. Biggest discount (up to 72%).

**Convertible RIs**: Can change instance family, size, OS, and tenancy at any time. Smaller discount (~54%).

**Scheduled RIs**: Reserve capacity for specific recurring time windows (e.g., peak hours Mon-Fri). Being deprecated in favor of Savings Plans.

**RI Marketplace**: Sell unused RIs you no longer need on the AWS Marketplace.

<ExamTip>
**Standard RI**: Locked to instance type and region. Highest discount. Use when you know your workload.
**Convertible RI**: Flexible. Can change instance type. Lower discount. Use when uncertain about future needs.
</ExamTip>

## Savings Plans

**Savings Plans** are a more flexible alternative to RIs. You commit to a dollar amount of compute usage per hour:

| Type | Flexibility | Discount |
|---|---|---|
| **Compute Savings Plans** | Any EC2 instance, any region, any OS; also Lambda and Fargate | Up to 66% |
| **EC2 Instance Savings Plans** | Specific instance family in a specific region | Up to 72% |
| **SageMaker Savings Plans** | SageMaker compute | Up to 64% |

**Compute Savings Plans** are the most flexible — if you move from m5.xlarge in us-east-1 to c5.2xlarge in eu-west-1, the savings plan automatically applies.

**Recommendation**: Use Cost Explorer's Savings Plans recommendations to find the optimal commitment amount.

## Spot Instances

**Spot Instances** use unused EC2 capacity at up to 90% discount. The catch: AWS can **reclaim** them with a 2-minute warning when capacity is needed.

**Spot lifecycle:**
1. You bid on unused capacity
2. Instance runs at the current Spot price
3. If AWS needs the capacity back → 2-minute interruption notice → instance terminates (or stops/hibernates)

**Spot best practices:**
- Design for interruption: save progress, handle graceful shutdown
- Use **Spot Fleet** or **EC2 Auto Scaling** with multiple instance types and AZs (a specific instance type may not always be available)
- **Spot Blocks** (1-6 hours): Reserved for a defined duration (being deprecated)

**Ideal Spot use cases:**
- Batch jobs and big data processing (Hadoop, Spark)
- CI/CD build pipelines
- ML training jobs (save checkpoints)
- Web scraping, scientific simulations
- Any stateless, fault-tolerant, flexible workload

**Never use Spot for:**
- Databases (data loss risk)
- Real-time production APIs (availability risk)
- Long-running stateful applications

## Dedicated Hosts vs. Dedicated Instances

**Dedicated Instances**: EC2 instances on hardware dedicated to your account (other customers' instances don't share the physical host). No control over placement.

**Dedicated Hosts**: A physical server fully dedicated to your use. You get visibility into sockets, cores, and host ID:
- Required for per-socket or per-core licensing (Windows Server, SQL Server, Oracle)
- Required for some compliance requirements
- Can purchase on-demand or as Reserved Hosts (discount)

## Combining Purchase Options in Auto Scaling

The most cost-effective approach uses **mixed instances policy** in EC2 Auto Scaling:
```
Minimum/baseline capacity: On-Demand or Reserved Instances
Additional capacity: Spot Instances (cheaper, but interruptible)

Example:
- 2 On-Demand base instances (always running)
- Additional capacity: 70% Spot, 30% On-Demand
- Multiple instance types: t3.large, m5.large, m4.large (prevents capacity loss from one type)
```

This is sometimes called "Spot + On-Demand hybrid" architecture.

## Summary

- **On-Demand**: No commitment, highest cost. For unpredictable workloads.
- **Reserved**: 1-3 year commitment. Up to 72% off. Standard (specific) vs. Convertible (flexible).
- **Savings Plans**: Dollar-per-hour commitment. More flexible than RIs.
- **Spot**: Up to 90% off. Can be interrupted with 2-min warning. For fault-tolerant workloads.
- **Dedicated Host**: Full server for you. For per-core licensing (Windows, SQL Server, Oracle).
- **Best practice**: Reserved/Savings Plans for baseline + Spot for variable load.
